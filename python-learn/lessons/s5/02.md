## 為什麼需要虛擬環境？

假設你有兩個專案：
- 專案 A 用 Django 4.2
- 專案 B 用 Django 5.1

如果都裝在電腦的同一個 Python 裡，就會**互相衝突**。**虛擬環境（virtual environment）** 讓每個專案有**自己獨立的套件**，互不干擾。

> 💡 好習慣：**每個專案都建立自己的虛擬環境**。

## 方法一：venv + pip（Python 內建）

### 1. 建立虛擬環境

在專案資料夾裡執行：

```bash
python -m venv .venv
```

會建立一個 `.venv` 資料夾，裡面是獨立的 Python。

### 2. 啟動虛擬環境

```bash
# Windows（PowerShell）
.venv\Scripts\Activate.ps1

# Windows（命令提示字元）
.venv\Scripts\activate.bat

# Mac / Linux
source .venv/bin/activate
```

成功後，終端機前面會出現 `(.venv)`。

> ⚠️ Windows PowerShell 如果出現「無法載入，因為這個系統上已停用指令碼執行」，先執行一次：
> `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

### 3. 安裝套件

```bash
pip install requests
pip install pandas==2.2.3        # 指定版本
pip install "fastapi[standard]"  # 包含額外功能
pip list                          # 列出已安裝的套件
pip uninstall requests
```

### 4. 記錄套件清單

```bash
pip freeze > requirements.txt     # 把目前的套件和版本存起來
pip install -r requirements.txt   # 在別台電腦一次裝回來
```

`requirements.txt` 長這樣：

```text
pandas==2.2.3
requests==2.32.3
```

### 5. 離開虛擬環境

```bash
deactivate
```

### VS Code 自動使用虛擬環境

建立 `.venv` 之後，VS Code 通常會自動偵測。如果沒有：<kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>P</kbd> → `Python: Select Interpreter` → 選 `.venv` 裡的 Python。

## 方法二：uv（新一代工具，非常快）

[uv](https://docs.astral.sh/uv/) 是用 Rust 寫的套件管理工具，比 pip **快 10～100 倍**，而且可以順便幫你安裝和管理 Python 版本。現在越來越多專案改用它。

### 安裝 uv

```bash
# Windows（PowerShell）
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

# Mac / Linux
curl -LsSf https://astral.sh/uv/install.sh | sh
```

### 用 uv 管理專案

```bash
uv init my-project        # 建立新專案（含 pyproject.toml）
cd my-project
uv add requests pandas    # 安裝套件（自動建立 .venv、自動記錄到 pyproject.toml）
uv add --dev pytest       # 只有開發時需要的套件
uv run main.py            # 在虛擬環境裡執行程式（不用手動 activate）
uv sync                   # 依照 pyproject.toml 安裝所有套件（換電腦時用）
uv python install 3.12    # 安裝其他版本的 Python
```

`uv add` 會自動更新 `pyproject.toml`，並產生 `uv.lock` 鎖定確切的版本，讓團隊每個人裝到完全一樣的套件。

## pip vs uv 對照表

| 做什麼 | pip / venv | uv |
|---|---|---|
| 建立環境 | `python -m venv .venv` | `uv venv`（`uv add` 時也會自動建立） |
| 安裝套件 | `pip install x` | `uv add x` |
| 移除套件 | `pip uninstall x` | `uv remove x` |
| 記錄套件 | `pip freeze > requirements.txt` | 自動寫入 `pyproject.toml` |
| 還原環境 | `pip install -r requirements.txt` | `uv sync` |
| 執行 | 先 activate，再 `python main.py` | `uv run main.py` |

> 💡 **初學建議**：先熟悉 venv + pip（到處都看得到），之後再換成 uv。兩個都會最好。

## .gitignore：不要把虛擬環境上傳到 GitHub

虛擬環境很大，而且每台電腦不一樣，**不要放進版本控制**。在專案根目錄建立 `.gitignore`：

```text
.venv/
__pycache__/
*.pyc
.env
```

上傳的是 `requirements.txt` 或 `pyproject.toml`，別人下載後自己建立環境。

## 在網頁上查看套件資訊

瀏覽器版的 Python 也可以查看已安裝套件的資訊：

```python
from importlib.metadata import version, PackageNotFoundError
import sys

print("Python 版本：", sys.version.split()[0])
for pkg in ["pip", "numpy", "requests", "not-a-real-package"]:
    try:
        print(f"{pkg:<20} {version(pkg)}")
    except PackageNotFoundError:
        print(f"{pkg:<20} （沒有安裝）")
```

def parse_requirements(text):
    result = {}
    for line in text.splitlines():
        line = line.strip()
        if not line or line.startswith("#"):
            continue
        if "==" in line:
            name, ver = line.split("==", 1)
            result[name.strip().lower()] = ver.strip()
        else:
            result[line.lower()] = None
    return result
