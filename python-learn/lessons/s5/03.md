## 為什麼不用 print 就好？

`print` 適合學習和快速測試，但在正式的程式裡：
- 沒辦法區分**重要程度**（一般資訊 vs 嚴重錯誤）
- 上線後想關掉除錯訊息，要一行一行刪
- 沒有**時間**、**來源**等資訊
- 不能同時寫到檔案

`logging` 模組解決了這些問題。

## 基本用法

```python
import logging

logging.basicConfig(
    level=logging.DEBUG,
    format="%(asctime)s [%(levelname)s] %(message)s",
    datefmt="%H:%M:%S",
    force=True,          # 網頁版需要：重新設定（自己電腦上第一次設定時可以省略）
)

logging.debug("除錯細節：x = 42")
logging.info("伺服器啟動在 port 8000")
logging.warning("磁碟空間剩下 10%")
logging.error("資料庫連線失敗")
logging.critical("系統即將關閉！")
```

## 五個等級

| 等級 | 數值 | 用途 |
|---|---|---|
| `DEBUG` | 10 | 開發時的詳細資訊 |
| `INFO` | 20 | 一般運作資訊（啟動、完成某件事） |
| `WARNING` | 30 | 有點不對勁，但還能運作（**預設等級**） |
| `ERROR` | 40 | 發生錯誤，某個功能失敗 |
| `CRITICAL` | 50 | 嚴重錯誤，程式可能無法繼續 |

設定 `level` 之後，**低於這個等級的訊息就不會顯示**。上線時改成 `INFO` 或 `WARNING`，除錯訊息就自動消失了：

```python
import logging

logging.basicConfig(level=logging.WARNING, format="[%(levelname)s] %(message)s", force=True)
logging.debug("看不到")
logging.info("也看不到")
logging.warning("看得到")
```

## 每個模組用自己的 logger

實務上不直接用 `logging.info()`，而是每個模組建立自己的 logger，這樣就知道訊息是**從哪裡來的**：

```python
import logging

logging.basicConfig(level=logging.INFO, format="%(name)-10s %(levelname)-7s %(message)s", force=True)

db_log = logging.getLogger("database")
api_log = logging.getLogger("api")

db_log.info("連線成功")
api_log.info("收到 GET /users")
api_log.warning("請求太頻繁：192.168.1.5")

logging.getLogger("database").setLevel(logging.WARNING)   # 只關掉資料庫的 INFO
db_log.info("這行看不到了")
api_log.info("API 的 INFO 還看得到")
```

在自己的檔案裡，慣例寫法是：

```py
import logging

logger = logging.getLogger(__name__)    # __name__ 是模組名稱，例如 "myapp.database"
```

## 記錄錯誤的完整資訊

在 `except` 裡用 `logger.exception()`，會**自動附上完整的錯誤追蹤**：

```python
import logging

logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s", force=True)
logger = logging.getLogger("payment")

def charge(amount):
    try:
        return 1000 / amount
    except ZeroDivisionError:
        logger.exception("扣款失敗，amount=%s", amount)    # 用 %s 傳參數
        return None

charge(0)
print("程式繼續執行")
```

> 💡 logging 的參數建議用 `logger.info("使用者 %s 登入", name)`，而不是 f-string。這樣如果該等級被關掉，就不會浪費時間組合字串。

## 同時輸出到畫面和檔案：Handler

```python
import logging

logger = logging.getLogger("app")
logger.setLevel(logging.DEBUG)
logger.handlers.clear()

console = logging.StreamHandler()                  # 輸出到畫面
console.setLevel(logging.INFO)
console.setFormatter(logging.Formatter("%(levelname)s: %(message)s"))

file = logging.FileHandler("app.log", encoding="utf-8")   # 輸出到檔案
file.setLevel(logging.DEBUG)                       # 檔案記錄更詳細
file.setFormatter(logging.Formatter("%(asctime)s %(name)s %(levelname)s %(message)s"))

logger.addHandler(console)
logger.addHandler(file)

logger.debug("只會寫進檔案")
logger.info("畫面和檔案都有")
logger.error("出錯了")

print("\n--- app.log 的內容 ---")
print(open("app.log", encoding="utf-8").read())
```

正式環境常用 `RotatingFileHandler`：檔案太大時自動換新檔，避免 log 塞爆硬碟。

## 格式化欄位

| 欄位 | 內容 |
|---|---|
| `%(asctime)s` | 時間 |
| `%(levelname)s` | 等級名稱 |
| `%(name)s` | logger 名稱 |
| `%(message)s` | 訊息 |
| `%(filename)s` `%(lineno)d` | 檔名、行號 |
| `%(funcName)s` | 函式名稱 |

import logging

logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s", force=True)
logger = logging.getLogger("orders")


def process(orders):
    n, total = 0, 0
    for o in orders:
        if o["amount"] <= 0:
            logger.warning("訂單 %s 金額異常：%s", o["id"], o["amount"])
            continue
        logger.info("訂單 %s 完成，金額 %s", o["id"], o["amount"])
        n += 1
        total += o["amount"]
    logger.info("共處理 %s 筆，總金額 %s", n, total)


process([{"id": "A1", "amount": 300}, {"id": "A2", "amount": 0}, {"id": "A3", "amount": 150}])
