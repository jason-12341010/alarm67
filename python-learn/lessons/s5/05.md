寫了很好用的程式，想讓別人也能用 `pip install` 安裝嗎？這一課介紹 Python 專案的標準結構，以及怎麼打包、發佈到 **PyPI**（Python 的官方套件庫）。

> ⚠️ 這一課的指令要在自己的電腦上執行。

## 專案結構

現在推薦的結構是 **src layout**：

```text
my-tools/
├── pyproject.toml        ← 專案設定（最重要的檔案）
├── README.md
├── LICENSE
├── src/
│   └── my_tools/         ← 套件本體（資料夾名稱用底線）
│       ├── __init__.py
│       ├── text.py
│       └── cli.py
└── tests/
    └── test_text.py
```

- **`__init__.py`**：讓資料夾變成一個「套件（package）」，可以被 import。可以是空的，也可以放要對外公開的東西
- **`tests/`**：測試放在套件外面

## 模組與套件的 import

```py
# src/my_tools/text.py
def slugify(text: str) -> str:
    return "-".join(text.lower().split())

# src/my_tools/__init__.py
from .text import slugify          # . 代表「同一個套件裡的」（相對匯入）

__version__ = "0.1.0"
__all__ = ["slugify"]

# 使用的人就可以這樣寫
from my_tools import slugify
```

## pyproject.toml

這是現代 Python 專案的**設定中心**：套件名稱、版本、相依套件、工具設定都寫在這裡。

```toml
[project]
name = "my-tools"
version = "0.1.0"
description = "一些好用的小工具"
readme = "README.md"
requires-python = ">=3.10"
authors = [{ name = "你的名字", email = "you@example.com" }]
dependencies = [
    "requests>=2.31",
]

[project.optional-dependencies]
dev = ["pytest>=8", "ruff"]

[project.scripts]
my-tools = "my_tools.cli:main"     # 安裝後可以在終端機直接輸入 my-tools 執行

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.ruff]
line-length = 100
```

## 開發模式安裝

開發時用 `-e`（editable）安裝，修改程式碼後**不用重新安裝**就會生效：

```bash
pip install -e ".[dev]"
```

或用 uv：

```bash
uv sync
```

## 命令列工具：argparse

`[project.scripts]` 指向的 `main` 函式，通常用 `argparse` 處理命令列參數：

```python
import argparse

def main(argv=None):
    parser = argparse.ArgumentParser(prog="my-tools", description="文字小工具")
    parser.add_argument("text", help="要處理的文字")
    parser.add_argument("-u", "--upper", action="store_true", help="轉成大寫")
    parser.add_argument("-n", "--repeat", type=int, default=1, help="重複幾次")
    args = parser.parse_args(argv)

    result = args.text.upper() if args.upper else args.text
    print(" ".join([result] * args.repeat))

# 模擬在終端機輸入：my-tools hello -u -n 3
main(["hello", "-u", "-n", "3"])
main(["--help"])
```

## 程式碼品質工具

| 工具 | 用途 | 指令 |
|---|---|---|
| **ruff** | 超快的檢查器 + 格式化（取代 flake8、black、isort） | `ruff check .`、`ruff format .` |
| **mypy** / **pyright** | 型別檢查 | `mypy src` |
| **pytest** | 測試 | `pytest` |
| **pre-commit** | 每次 git commit 前自動執行以上工具 | `pre-commit install` |

## 打包與發佈

```bash
pip install build twine
python -m build                  # 產生 dist/ 資料夾，裡面有 .whl 和 .tar.gz
twine upload --repository testpypi dist/*   # 先上傳到測試用的 TestPyPI
twine upload dist/*              # 正式發佈到 PyPI
```

用 uv 的話：

```bash
uv build
uv publish
```

發佈之後，全世界的人都可以 `pip install my-tools` 了！

> 💡 第一次練習請先發佈到 [TestPyPI](https://test.pypi.org/)，確認沒問題再發佈到正式的 PyPI。套件名稱不能和現有的重複。

## 版本號：語意化版本（SemVer）

`主版本.次版本.修訂號`，例如 `2.4.1`：
- **主版本**：有**不相容**的修改（使用者的程式可能要改）
- **次版本**：新增功能，但向下相容
- **修訂號**：修正 bug

```python
def bump(version: str, part: str) -> str:
    major, minor, patch = map(int, version.split("."))
    if part == "major":
        return f"{major + 1}.0.0"
    if part == "minor":
        return f"{major}.{minor + 1}.0"
    return f"{major}.{minor}.{patch + 1}"

v = "1.4.2"
for part in ["patch", "minor", "major"]:
    print(f"{v} --{part}--> {bump(v, part)}")
```

import argparse


def main(argv=None):
    parser = argparse.ArgumentParser(prog="calc")
    parser.add_argument("numbers", nargs="+", type=float)
    parser.add_argument("--op", choices=["sum", "avg", "max"], default="sum")
    args = parser.parse_args(argv)
    if args.op == "sum":
        result = sum(args.numbers)
    elif args.op == "avg":
        result = sum(args.numbers) / len(args.numbers)
    else:
        result = max(args.numbers)
    print(int(result) if result == int(result) else result)
