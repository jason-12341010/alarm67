## 為什麼要寫測試？

每次修改程式，你怎麼確定**沒有把原本正常的功能弄壞**？一個一個手動試太累了。**自動化測試**就是寫程式來檢查程式。

> 💡 其實你在這個網站上做的每一題練習，背後都有一段「測試程式」在檢查你的答案！

## 最簡單的測試：assert

```python
def add(a, b):
    return a + b

assert add(2, 3) == 5
assert add(-1, 1) == 0
assert add(0.1, 0.2) == 0.3, "浮點數誤差！"     # 這行會失敗
print("全部通過")
```

## pytest：最受歡迎的測試框架

規則很簡單：
1. 測試檔案名稱以 `test_` 開頭（例如 `test_calc.py`）
2. 測試函式名稱以 `test_` 開頭
3. 用一般的 `assert` 檢查

在自己的電腦上：

```bash
pip install pytest
pytest              # 自動找出所有 test_*.py 並執行
pytest -v           # 顯示每個測試的名稱
pytest -k "add"     # 只跑名稱包含 add 的測試
```

瀏覽器版的 Python 也有 pytest，我們把程式和測試寫成檔案，再呼叫 `pytest.main()` 執行：

```python
from pathlib import Path
import pytest

Path("calc.py").write_text('''
def add(a, b):
    return a + b

def divide(a, b):
    if b == 0:
        raise ValueError("不能除以 0")
    return a / b
''', encoding="utf-8")

Path("test_calc.py").write_text('''
import pytest
from calc import add, divide

def test_add():
    assert add(2, 3) == 5

def test_add_negative():
    assert add(-1, -1) == -2

def test_divide():
    assert divide(10, 4) == 2.5

def test_divide_by_zero():
    with pytest.raises(ValueError, match="不能除以 0"):   # 確認會丟出正確的錯誤
        divide(1, 0)

def test_float():
    assert add(0.1, 0.2) == pytest.approx(0.3)   # 浮點數用 approx 比較
''', encoding="utf-8")

pytest.main(["-v", "-p", "no:cacheprovider", "test_calc.py"])
```

試著把 `calc.py` 裡的 `a + b` 改成 `a - b` 再執行，看看失敗時 pytest 會給你什麼資訊。

## 參數化：一次測很多組資料

```python
from pathlib import Path
import pytest

Path("test_param.py").write_text('''
import pytest

def is_leap(year):
    return (year % 4 == 0 and year % 100 != 0) or year % 400 == 0

@pytest.mark.parametrize("year, expected", [
    (2024, True),
    (2023, False),
    (1900, False),
    (2000, True),
])
def test_is_leap(year, expected):
    assert is_leap(year) == expected
''', encoding="utf-8")

pytest.main(["-v", "-p", "no:cacheprovider", "test_param.py"])
```

## fixture：準備測試資料

很多測試需要同樣的準備工作（建立物件、連資料庫…），用 **fixture** 共用：

```python
from pathlib import Path
import pytest

Path("test_cart.py").write_text('''
import pytest

class Cart:
    def __init__(self):
        self.items = {}
    def add(self, name, price, qty=1):
        self.items[name] = (price, self.items.get(name, (price, 0))[1] + qty)
    def total(self):
        return sum(p * q for p, q in self.items.values())

@pytest.fixture
def cart():                      # 每個用到 cart 的測試，都會拿到一個全新的購物車
    c = Cart()
    c.add("蘋果", 30, 2)
    return c

def test_total(cart):
    assert cart.total() == 60

def test_add_more(cart):
    cart.add("蘋果", 30)
    assert cart.items["蘋果"] == (30, 3)

def test_independent(cart):      # 上一個測試的修改不會影響這裡
    assert cart.total() == 60
''', encoding="utf-8")

pytest.main(["-q", "-p", "no:cacheprovider", "test_cart.py"])
```

## 好的測試要測什麼？

1. **正常情況**：一般的輸入
2. **邊界情況**：0、空串列、空字串、最大值、最小值
3. **錯誤情況**：不合法的輸入是否正確地丟出錯誤

```python
def average(nums):
    return sum(nums) / len(nums)

# 正常
assert average([1, 2, 3]) == 2
# 邊界：只有一個元素
assert average([5]) == 5
# 邊界：空串列 → 會發生什麼事？
try:
    average([])
except ZeroDivisionError:
    print("⚠️ 找到 bug：空串列會出錯，要決定該怎麼處理")
```

## 測試驅動開發（TDD）

一種開發方式：**先寫測試，再寫程式**。
1. 🔴 寫一個會失敗的測試
2. 🟢 寫剛好能通過測試的程式
3. 🔵 重構，讓程式更好（測試保證沒改壞）

## 標準函式庫的 unittest

Python 內建的測試框架，寫法比較囉嗦（要寫 class），但不用安裝。在舊專案很常見：

```python
import unittest

def slugify(text):
    return "-".join(text.lower().split())

class TestSlugify(unittest.TestCase):
    def test_basic(self):
        self.assertEqual(slugify("Hello World"), "hello-world")

    def test_spaces(self):
        self.assertEqual(slugify("  a   b  "), "a-b")

    def test_empty(self):
        self.assertEqual(slugify(""), "")

unittest.main(argv=["x"], exit=False, verbosity=2)
```

:::exercise 幫函式寫測試
`is_valid_password(pw)` 的規則是：長度至少 8、至少一個大寫字母、至少一個數字。

請在 `test_cases` 裡填入**至少 6 組**測試資料 `(密碼, 預期結果)`，要包含：至少 2 組 `True`、以及「太短」、「沒有大寫」、「沒有數字」這三種 `False` 的情況。檢查程式會用你的測試資料去測試**幾個有 bug 的版本**，你的測試要能**抓出所有的 bug**！
@@starter
def is_valid_password(pw):
    return len(pw) >= 8 and any(c.isupper() for c in pw) and any(c.isdigit() for c in pw)


test_cases = [
    ("Password1", True),
]

for pw, expected in test_cases:
    assert is_valid_password(pw) == expected, f"{pw!r} 應該是 {expected}"
print(f"✓ {len(test_cases)} 組測試都通過")
