LLM 只會產生文字。但如果讓它可以**使用工具**：查天氣、搜尋資料庫、寄 email、執行程式… 它就從「聊天機器人」變成能**完成任務**的 **AI Agent**。

## 工具呼叫（Tool Use）的流程

```text
1. 你：提供問題 + 工具清單（每個工具的名稱、說明、參數格式）
2. 模型：「我需要呼叫 get_weather，參數是 {"city": "台北"}」
3. 你的程式：真的去執行 get_weather("台北")，得到結果
4. 你：把結果傳回給模型
5. 模型：根據結果回答，或是再呼叫其他工具…（重複 2～4）
6. 模型：「台北現在 25 度，晴天，適合出門！」
```

> 💡 重點：**模型不會自己執行工具**，它只是決定「要用哪個工具、參數是什麼」。真正執行的是**你的程式**。所以你可以控制它能做什麼、不能做什麼。

## 用 Claude 的工具呼叫

### 方法一：Tool Runner（推薦，SDK 幫你跑迴圈）

用 `@beta_tool` 把一般的 Python 函式變成工具，函式的**型別提示和 docstring** 會自動變成工具的說明（還記得第 4 階段的型別提示嗎？）：

```py
import anthropic
from anthropic import beta_tool

client = anthropic.Anthropic()

@beta_tool
def get_weather(city: str) -> str:
    """查詢城市目前的天氣。

    Args:
        city: 城市名稱，例如「台北」。
    """
    fake_data = {"台北": "25°C 晴天", "高雄": "30°C 多雲"}       # 實際上會呼叫氣象 API
    return fake_data.get(city, "查無此城市")

@beta_tool
def calculator(expression: str) -> str:
    """計算數學算式，例如 "(3 + 4) * 2"。

    Args:
        expression: 只包含數字和 + - * / ( ) 的算式。
    """
    if not set(expression) <= set("0123456789+-*/(). "):
        return "錯誤：算式包含不允許的字元"
    return str(eval(expression))

runner = client.beta.messages.tool_runner(
    model="claude-opus-5-5",
    max_tokens=4096,
    tools=[get_weather, calculator],
    messages=[{"role": "user", "content": "台北和高雄現在溫度差幾度？"}],
)
for message in runner:                         # 每一輪模型的回應
    for block in message.content:
        if block.type == "tool_use":
            print(f"🔧 呼叫 {block.name}({block.input})")
        elif block.type == "text":
            print(f"💬 {block.text}")
```

模型會自己決定：先查台北、再查高雄、再用計算機算差值，最後回答。

### 方法二：自己寫迴圈

想完全掌控每一步時，可以自己寫。工具要用 **JSON Schema** 描述參數：

```py
import anthropic, json

client = anthropic.Anthropic()
tools = [{
    "name": "get_weather",
    "description": "查詢城市目前的天氣",
    "input_schema": {
        "type": "object",
        "properties": {"city": {"type": "string", "description": "城市名稱"}},
        "required": ["city"],
    },
}]

def run_tool(name, args):
    if name == "get_weather":
        return {"台北": "25°C 晴天"}.get(args["city"], "查無此城市")
    return f"未知的工具：{name}"

messages = [{"role": "user", "content": "台北天氣如何？"}]
while True:
    response = client.messages.create(model="claude-opus-5-5", max_tokens=4096, tools=tools, messages=messages)
    if response.stop_reason != "tool_use":          # 不需要再用工具 → 結束
        break
    messages.append({"role": "assistant", "content": response.content})
    results = []
    for block in response.content:
        if block.type == "tool_use":
            results.append({
                "type": "tool_result",
                "tool_use_id": block.id,            # 一定要對應到 tool_use 的 id
                "content": run_tool(block.name, block.input),
            })
    messages.append({"role": "user", "content": results})   # 所有結果放在同一則訊息

print("".join(b.text for b in response.content if b.type == "text"))
```

## 在網頁上體驗：Agent 迴圈模擬器

我們用一個「假的 LLM」（用簡單的規則決定要呼叫哪個工具），來看清楚 Agent 迴圈的每一步。**結構和真正的程式一模一樣**：

```python
import json

# ---------- 工具 ----------
def get_weather(city):
    return {"台北": 25, "高雄": 30, "台中": 27}.get(city, None)

def calculator(expression):
    if not set(expression) <= set("0123456789+-*/(). "):
        raise ValueError("不允許的字元")
    return eval(expression)

TOOLS = {"get_weather": get_weather, "calculator": calculator}

# ---------- 假的 LLM：看對話紀錄決定下一步 ----------
def fake_llm(messages):
    tool_results = [m for m in messages if m["role"] == "tool"]
    if len(tool_results) == 0:
        return {"tool": "get_weather", "args": {"city": "台北"}}
    if len(tool_results) == 1:
        return {"tool": "get_weather", "args": {"city": "高雄"}}
    if len(tool_results) == 2:
        a, b = tool_results[0]["content"], tool_results[1]["content"]
        return {"tool": "calculator", "args": {"expression": f"{b} - {a}"}}
    return {"answer": f"高雄比台北熱 {tool_results[2]['content']} 度。"}

# ---------- Agent 迴圈 ----------
messages = [{"role": "user", "content": "台北和高雄溫度差幾度？"}]
for step in range(1, 10):                       # 設定上限，避免無窮迴圈
    decision = fake_llm(messages)
    if "answer" in decision:
        print(f"💬 最終回答：{decision['answer']}")
        break
    name, args = decision["tool"], decision["args"]
    print(f"第 {step} 步 🔧 {name}({json.dumps(args, ensure_ascii=False)})", end=" → ")
    try:
        result = TOOLS[name](**args)
    except Exception as e:
        result = f"錯誤：{e}"                  # 錯誤也要回報給模型，讓它可以調整
    print(result)
    messages.append({"role": "tool", "content": result})
```

## Agent 的設計原則

| 原則 | 說明 |
|---|---|
| **工具說明要清楚** | 模型完全依靠名稱和說明決定怎麼用，寫得像給新同事的文件 |
| **權限最小化** | 只給完成任務需要的工具；刪除、付款這類危險操作要**人類確認** |
| **錯誤要回報** | 工具失敗時把錯誤訊息傳回去，模型常常可以自己修正 |
| **設定上限** | 最多幾步、最多花多少錢，避免無止盡地跑下去 |
| **先簡單再複雜** | 很多任務一次 API 呼叫或固定流程就能解決，不一定需要 Agent |

> ⚠️ **安全**：工具的輸入來自模型，模型的輸入可能來自使用者或網頁內容。**永遠要檢查工具的參數**（像上面的計算機只允許數字和運算符號），不要直接 `eval` 或執行任意指令。

## 更進一步

- **MCP（Model Context Protocol）**：一個開放的標準，讓 AI 應用可以用統一的方式接上各種工具和資料來源（GitHub、Google Drive、資料庫…）
- **Claude Agent SDK**：Anthropic 提供的套件，內建讀寫檔案、執行指令等工具，就是 Claude Code 背後的那一套
- **多 Agent 系統**：多個 Agent 分工合作，例如一個負責研究、一個負責寫作

def execute_tool(name, args, tools):
    if name not in tools:
        return {"is_error": True, "content": f"未知的工具：{name}"}
    try:
        result = tools[name](**args)
    except Exception as e:
        return {"is_error": True, "content": f"{type(e).__name__}: {e}"}
    return {"is_error": False, "content": str(result)}
