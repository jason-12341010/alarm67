同一個模型，**問法不同，回答的品質可以差很多**。設計好的提示詞（prompt）是使用 AI 最重要的技能之一，也叫做**提示工程（Prompt Engineering）**。

## 原則 1：清楚、具體，提供背景

把模型想成一位**聰明但完全不了解你狀況的新同事**。

```text
❌ 幫我寫一封信

✅ 幫我寫一封 email 給客戶王先生。
   背景：他上週訂購的 50 台筆電，因為缺貨會延遲 5 天出貨。
   目的：道歉、說明新的出貨日期（11/20），並提供 5% 折扣作為補償。
   語氣：正式但誠懇。長度：150 字以內。
```

好的提示詞包含：**背景、任務、限制（長度、格式、語氣）、為什麼要這樣做**。

## 原則 2：給範例（Few-shot）

與其用文字描述格式，不如**直接示範**：

```text
把客戶的抱怨分類，並給出建議的處理部門。

範例：
輸入：「包裹寄錯地址了」
輸出：{"類別": "物流", "部門": "倉儲物流部"}

輸入：「信用卡被重複扣款」
輸出：{"類別": "帳務", "部門": "財務部"}

現在請處理：
輸入：「收到的衣服有破洞」
```

## 原則 3：用標籤區分不同的內容

提示詞裡有**資料**又有**指示**時，用 XML 標籤包起來，模型比較不會搞混：

```text
請摘要下面的會議紀錄，列出：決議事項、待辦事項（含負責人）。

<meeting_notes>
（這裡貼上會議紀錄）
</meeting_notes>

輸出格式：
<summary>…</summary>
<todos>…</todos>
```

這也能降低「**提示詞注入（prompt injection）**」的風險：如果使用者貼上的資料裡寫著「忽略之前的指示」，模型比較知道那只是資料，不是命令。

## 原則 4：讓模型一步一步想

複雜的問題，請模型**先分析再回答**，準確率會提高很多：

```text
小明有 3 盒蘋果，每盒 12 顆。他送給 5 位朋友每人 4 顆，自己吃了 3 顆。還剩幾顆？
請先列出每一步的計算，最後再寫出答案。
```

> 💡 新一代的模型（像 Claude）內建「思考」能力，遇到困難的問題會自己先推理。但清楚告訴它你要的步驟和格式，一樣很有幫助。

## 原則 5：指定輸出格式

要讓**程式**處理模型的回答時，請它用 **JSON** 這種固定的格式輸出，程式就能直接解析：

```python
import json

# 假設這是模型回傳的文字
reply = """{
  "sentiment": "negative",
  "topics": ["物流", "客服"],
  "urgency": 4,
  "summary": "訂單延遲一週且聯絡不到客服"
}"""
data = json.loads(reply)
if data["urgency"] >= 4:
    print(f"🚨 緊急案件：{data['summary']}（主題：{'、'.join(data['topics'])}）")
```

Claude API 也有**結構化輸出**功能，可以保證回傳的 JSON 一定符合你指定的格式（用 Pydantic 定義），第 6 階段學 FastAPI 時會用到 Pydantic。

## 用程式組合提示詞：模板

實務上，提示詞通常是**模板 + 資料**：

```python
TEMPLATE = """你是一位專業的{role}。

請根據以下的產品資訊，寫一段{length}字以內的{style}商品介紹。

<product>
名稱：{name}
特色：{features}
價格：{price} 元
</product>

只輸出介紹文字，不要加任何前言。"""

prompt = TEMPLATE.format(
    role="電商文案寫手",
    length=80,
    style="活潑、適合年輕人的",
    name="無線藍牙耳機 X1",
    features="、".join(["降噪", "續航 30 小時", "IPX5 防水"]),
    price=1290,
)
print(prompt)
```

## 評估提示詞：不要只憑感覺

改了提示詞之後，怎麼知道有沒有變好？準備一組**測試案例**，自動檢查結果，就像第 5 階段學的測試：

```python
import json

test_cases = [
    {"input": "東西很好用，下次還會再買", "expected": "positive"},
    {"input": "等了兩週還沒到貨", "expected": "negative"},
    {"input": "包裝有點簡陋，但商品沒問題", "expected": "neutral"},
]

def fake_model(text):          # 實際上這裡會呼叫 API
    if "還會" in text or "好用" in text:
        return '{"sentiment": "positive"}'
    if "沒到" in text:
        return '{"sentiment": "negative"}'
    return '{"sentiment": "positive"}'

correct = 0
for case in test_cases:
    got = json.loads(fake_model(case["input"]))["sentiment"]
    ok = got == case["expected"]
    correct += ok
    print(f"{'✅' if ok else '❌'} {case['input']:<16} 預期 {case['expected']:<9} 得到 {got}")
print(f"正確率：{correct / len(test_cases):.0%}")
```

## 提示詞常見問題

| 問題 | 解法 |
|---|---|
| 回答太長、太囉嗦 | 明確指定長度、「只輸出 ○○」 |
| 編造事實（幻覺） | 提供參考資料，並說「資料裡沒有就說不知道」（下兩課的 RAG） |
| 格式不穩定 | 給範例、用 JSON、用結構化輸出 |
| 理解錯誤 | 補充背景和目的，說明**為什麼** |

def build_prompt(task, examples, query):
    blocks = "\n\n".join(f"輸入：{i}\n輸出：{o}" for i, o in examples)
    inner = f"{blocks}\n" if blocks else ""
    return f"任務：{task}\n\n<examples>\n{inner}</examples>\n\n輸入：{query}\n輸出："
