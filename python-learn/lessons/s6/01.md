## 瀏覽網頁時發生了什麼事？

```text
你的瀏覽器（客戶端 Client）                  網站的電腦（伺服器 Server）
        │                                            │
        │  ① HTTP 請求（Request）                     │
        │  GET /products?page=2                      │
        │ ─────────────────────────────────────────→ │
        │                                            │  ② 伺服器上的 Python 程式
        │                                            │     查資料庫、組合網頁
        │  ③ HTTP 回應（Response）                    │
        │  200 OK + HTML / JSON                      │
        │ ←───────────────────────────────────────── │
```

Flask、FastAPI、Django 這些**框架**，就是幫你處理第 ② 步：收到請求 → 執行你的 Python 函式 → 回傳結果。

## 網址（URL）的組成

```python
from urllib.parse import urlparse, parse_qs

url = "https://shop.example.com:443/products/search?q=耳機&page=2#reviews"
u = urlparse(url)
print("協定 scheme：", u.scheme)
print("網域 host：  ", u.hostname)
print("埠號 port：  ", u.port)
print("路徑 path：  ", u.path)
print("查詢 query： ", parse_qs(u.query))
print("錨點 fragment：", u.fragment)
```

## HTTP 方法：你想做什麼？

| 方法 | 用途 | 例子 |
|---|---|---|
| **GET** | 讀取資料 | 看商品列表、看文章 |
| **POST** | 新增資料 | 註冊帳號、送出訂單 |
| **PUT / PATCH** | 修改資料 | 更新個人資料 |
| **DELETE** | 刪除資料 | 刪除留言 |

## HTTP 狀態碼：結果如何？

| 範圍 | 意思 | 常見的 |
|---|---|---|
| **2xx** 成功 | 一切順利 | `200 OK`、`201 Created`、`204 No Content` |
| **3xx** 重新導向 | 東西搬家了 | `301 永久搬家`、`302 暫時搬家` |
| **4xx** 客戶端錯誤 | **你**的請求有問題 | `400 格式錯誤`、`401 沒登入`、`403 沒權限`、`404 找不到`、`422 資料驗證失敗`、`429 太頻繁` |
| **5xx** 伺服器錯誤 | **網站**壞掉了 | `500 程式出錯`、`503 暫時無法服務` |

```python
from http import HTTPStatus

for code in [200, 201, 301, 400, 401, 403, 404, 422, 500, 503]:
    s = HTTPStatus(code)
    print(code, s.phrase)
```

## 請求和回應長什麼樣子？

HTTP 其實就是**純文字**：

```text
POST /api/orders HTTP/1.1            ← 方法、路徑、版本
Host: shop.example.com               ← 標頭（Headers）
Content-Type: application/json
Authorization: Bearer abc123

{"product_id": 42, "qty": 2}         ← 內容（Body）
```

```text
HTTP/1.1 201 Created                 ← 狀態碼
Content-Type: application/json

{"order_id": 1001, "total": 2580}
```

## 網頁 vs API

| | 網頁（Web Page） | API |
|---|---|---|
| 給誰看 | **人**（瀏覽器顯示） | **程式**（App、其他網站、AI） |
| 回傳格式 | HTML | 通常是 **JSON** |
| 適合的框架 | Flask、Django | **FastAPI**、Flask、Django REST Framework |

現在很多網站是「**前後端分離**」：後端（Python）只提供 API 回傳 JSON，前端（React、Vue、手機 App）負責畫面。

## REST API 的設計慣例

用**名詞**當路徑、用 **HTTP 方法**表示動作：

| 動作 | 方法 + 路徑 |
|---|---|

## 自己寫一個「迷你框架」

框架到底在做什麼？其實核心概念很簡單：**把網址對應到函式**。我們用 Python 模擬一個：

```python
import json
import re

routes = []

def route(method, pattern):
    """裝飾器：登記「方法 + 網址」對應到哪個函式（第 4 階段學的裝飾器！）"""
    def decorator(func):
        regex = "^" + re.sub(r"<(\w+)>", r"(?P<\1>[^/]+)", pattern) + "$"
        routes.append((method, re.compile(regex), func))
        return func
    return decorator

PRODUCTS = {1: {"name": "耳機", "price": 1290}, 2: {"name": "滑鼠", "price": 590}}

@route("GET", "/products")
def list_products():
    return 200, list(PRODUCTS.values())

@route("GET", "/products/<pid>")
def get_product(pid):
    p = PRODUCTS.get(int(pid))
    return (200, p) if p else (404, {"error": "找不到商品"})

def handle(method, path):
    for m, regex, func in routes:
        match = regex.match(path)
        if m == method and match:
            status, body = func(**match.groupdict())
            return status, json.dumps(body, ensure_ascii=False)
    return 404, json.dumps({"error": "找不到這個網址"}, ensure_ascii=False)

for req in [("GET", "/products"), ("GET", "/products/2"), ("GET", "/products/9"), ("POST", "/products")]:
    print(req, "→", *handle(*req))
```

你接下來會在 Flask 看到幾乎一模一樣的寫法：`@app.route("/products/<pid>")`。

from urllib.parse import urlparse, parse_qs


def parse_request(url):
    u = urlparse(url)
    params = {k: v[0] for k, v in parse_qs(u.query).items()}
    return {"path": u.path, "params": params, "page": int(params.get("page", 1))}
