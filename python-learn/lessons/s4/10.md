## 三種「同時做很多事」的方式

| 方式 | 原理 | 適合 |
|---|---|---|
| **async**（上一課） | 一個執行緒，在等待時切換工作 | 大量 I/O（網路、檔案） |
| **多執行緒 threading** | 一個行程裡有多個執行緒，**共用記憶體** | I/O 密集的工作，或使用不支援 async 的函式庫 |
| **多行程 multiprocessing** | 開多個獨立的 Python 行程，**各自有記憶體** | **CPU 密集**的計算 |

## GIL：Python 的全域直譯器鎖

CPython 有一個 **GIL（Global Interpreter Lock）**：**同一時間只有一個執行緒能執行 Python 程式碼**。所以：

- 執行緒在**等待 I/O** 時會釋放 GIL → 多執行緒對**下載、讀檔**有幫助 ✅
- **純計算**時，多執行緒**不會變快**，因為一次只能跑一個 ❌ → 要用**多行程**

> 💡 Python 3.13 開始有實驗性的「無 GIL」版本（free-threaded），未來多執行緒可能也能加速計算。另外 NumPy、PyTorch 這類套件在 C 語言層計算時會釋放 GIL，所以它們本身就能用滿多個 CPU 核心。

## threading：多執行緒

```py
import threading
import time

def download(name):
    print(f"開始 {name}")
    time.sleep(1)                    # 等待 I/O 時會釋放 GIL
    print(f"完成 {name}")

start = time.perf_counter()
threads = [threading.Thread(target=download, args=(f"檔案{i}",)) for i in range(5)]
for t in threads:
    t.start()                        # 開始執行
for t in threads:
    t.join()                         # 等待全部結束
print(f"總共 {time.perf_counter() - start:.1f} 秒")   # 約 1 秒，不是 5 秒
```

## ⚠️ 競爭條件（race condition）與 Lock

多個執行緒同時修改同一個變數，結果可能會錯：

```py
import threading

count = 0
lock = threading.Lock()

def add_unsafe():
    global count
    for _ in range(100_000):
        count += 1                   # 讀取 → 加一 → 寫回，中間可能被打斷

def add_safe():
    global count
    for _ in range(100_000):
        with lock:                   # 同一時間只有一個執行緒能進來
            count += 1

for func in (add_unsafe, add_safe):
    count = 0
    threads = [threading.Thread(target=func) for _ in range(4)]
    for t in threads: t.start()
    for t in threads: t.join()
    print(func.__name__, count)      # unsafe 可能不是 400000
```

## concurrent.futures：最推薦的寫法

`ThreadPoolExecutor` 和 `ProcessPoolExecutor` 用法幾乎一樣，**換一個字就能從多執行緒換成多行程**：

```py
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor, as_completed
import time
import urllib.request

URLS = ["https://www.python.org", "https://pypi.org", "https://docs.python.org"]

def fetch(url):
    with urllib.request.urlopen(url, timeout=10) as r:
        return url, len(r.read())

# I/O 密集 → 執行緒池
with ThreadPoolExecutor(max_workers=5) as pool:
    futures = [pool.submit(fetch, u) for u in URLS]
    for f in as_completed(futures):          # 誰先完成就先處理誰
        url, size = f.result()
        print(f"{url}: {size:,} bytes")


def is_prime(n):
    if n < 2:
        return False
    return all(n % d for d in range(2, int(n ** 0.5) + 1))

NUMS = [112272535095293, 112582705942171, 115280095190773, 115797848077099] * 2

if __name__ == "__main__":                   # 多行程在 Windows 上一定要有這行！
    t = time.perf_counter()
    print([is_prime(n) for n in NUMS])
    print(f"單一行程：{time.perf_counter() - t:.1f} 秒")

    t = time.perf_counter()
    with ProcessPoolExecutor() as pool:      # CPU 密集 → 行程池，用滿所有 CPU 核心
        print(list(pool.map(is_prime, NUMS)))
    print(f"多行程：{time.perf_counter() - t:.1f} 秒")
```

> ⚠️ 使用 multiprocessing 時，主程式一定要放在 `if __name__ == "__main__":` 底下，否則在 Windows 和 macOS 上會無限建立新行程而出錯。

## 執行緒之間傳遞資料：queue

生產者－消費者模式，`queue.Queue` 是**執行緒安全**的：

```py
import threading, queue, time

q = queue.Queue()

def producer():
    for i in range(5):
        q.put(f"訂單{i}")
        time.sleep(0.1)
    q.put(None)                      # 結束訊號

def consumer():
    while (item := q.get()) is not None:
        print("處理", item)

threading.Thread(target=producer).start()
consumer()
```

## 怎麼選？

```
你的程式慢在哪裡？
├── 等待網路、檔案、資料庫（I/O）
│   ├── 使用的函式庫支援 async → asyncio
│   └── 不支援（例如 requests）→ ThreadPoolExecutor
└── 大量計算（CPU）
    ├── 能用 NumPy / pandas 向量化 → 先向量化！通常快 100 倍
    └── 純 Python 迴圈 → ProcessPoolExecutor
```

在 AI 和資料科學領域，最重要的加速方式其實是**向量化**（第 7 階段 NumPy 會教），而不是多執行緒。
